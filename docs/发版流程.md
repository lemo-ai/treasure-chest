# 发版流程

> 以后重新打 tag、发 GitHub Release，按本文操作即可。  
> 安装包由 GitHub Actions 云端打包上传，**不要**再本机慢传 DMG。

仓库：https://github.com/lemo-ai/treasure-chest  
工作流：`.github/workflows/release.yml`  
远程约定：`origin` = Codeup，`github` = GitHub（两边都推）。

---

## 0. 发版前检查

- [ ] 功能已在本机验证（`npm run typecheck` / 必要手动测）
- [ ] 工作区干净，或即将一并提交的改动已整理好
- [ ] 决定版本号：遵循语义化，如 `0.4.0` → `0.4.1` / `0.5.0`
- [ ] 本机已能 `git push github`（个人号对 `lemo-ai/treasure-chest` 有写权限）
- [ ] 本机已 `gh auth login`（仅在要用 `gh` 看 Actions / 手搓 Release 时需要）

---

## 1. 改版本与更新日志

### 1.1 `package.json`

把 `"version"` 改成新版本，例如 `"0.5.0"`（**不要**带 `v` 前缀）。

### 1.2 `config/changelog.json`

在 `releases` 数组**最前面**新增一条（应用内「版本变更」和 Actions Release 说明都读这里）：

```json
{
  "version": "0.5.0",
  "date": "2026-09-20",
  "title": {
    "zh-CN": "一句话中文标题",
    "en-US": "One-line English title"
  },
  "items": {
    "zh-CN": [
      "变更点 1",
      "变更点 2"
    ],
    "en-US": [
      "Change 1",
      "Change 2"
    ]
  }
}
```

`version` 必须与 `package.json` 一致；中英文都要写。

## 2. 提交并推送到 GitHub（以及 Codeup）

在仓库根目录：

```bash
cd /path/to/treasure-chest

git status
git add -A   # 或只 add 本次相关文件
git commit -m "chore: release 0.5.0"

# 双远程都推（顺序随意）
git push origin master
git push github master
```

确认 GitHub 上 `master` 已是最新提交：  
https://github.com/lemo-ai/treasure-chest/commits/master

---

## 3. 打 tag 并推送（触发自动打包）

标签格式必须是 **`v` + 版本号**，且与 `package.json` 一致，例如版本 `0.5.0` → tag `v0.5.0`。

### 3.1 新版本（推荐）

```bash
git tag -a v0.5.0 -m "v0.5.0"
git push github v0.5.0
git push origin v0.5.0   # Codeup 同步一份，可选但建议
```

推送 `v*` 到 GitHub 后，会自动跑 **Release** workflow：多平台打包并把产物挂到 Release Assets。

### 3.2 同一版本需要「重打 tag」再发一次

仅当：上次构建失败、或 tag 指错了提交、需要在**同一版本号**上重新发布。

```bash
# 1）如已有正式/草稿 Release，先删掉（保留或不保留 tag 按情况）
gh release delete v0.5.0 --repo lemo-ai/treasure-chest --yes

# 2）删远程 + 本地 tag
git push github :refs/tags/v0.5.0
git push origin :refs/tags/v0.5.0   # 若 Codeup 也有
git tag -d v0.5.0

# 3）在正确的 commit 上重建并推送（会再次触发 Actions）
git checkout master
git pull github master
git tag -a v0.5.0 -m "v0.5.0"
git push github v0.5.0
git push origin v0.5.0
```

注意：

- **不要**对已有 tag 用 `git push --force` 乱指，除非明确要覆盖；上面「先删再重建」更清晰  
- 删 Release 时**不要**加 `--cleanup-tag`，除非你打算马上重建 tag；误加会把远程 tag 一起删掉  
- 用户若已下载旧包，同版本重发可能造成混淆；能升小版本（`0.5.1`）更稳妥  

### 3.3 不重打 tag，只对已有 tag 再跑一遍构建

Actions → **Release** → **Run workflow** → 填入已有 tag（如 `v0.5.0`）→ Run。  
适用于：workflow 修好了、想对旧 tag 补传产物。

| 改版本 | `package.json` → `version` |

## 6. 常见问题

**Q: 推了 tag 但没有跑 Release？**  
确认 tag 名是 `v0.5.0` 这种（以 `v` 开头）；确认推的是 `github` 远程；到 Actions 看是否被 concurrency 取消或权限失败。

**Q: prepare 报 changelog 对不上？**  
`config/changelog.json` 里必须有与 tag 去掉 `v` 后相同的 `version` 字段。

**Q: 某一端（如 Windows）失败？**  
看对应 job 日志；修代码或 workflow 后，用 §3.2 重打 tag，或 §3.3 手动 Run workflow。

**Q: 还要不要本机 `npm run dist`？**  
日常发版不需要。本机 dist 只用于自己验证安装包；正式对外以 Actions 产物为准。

**Q: Codeup 和 GitHub 不一致？**  
发版以 GitHub 为准；平时养成 `origin` + `github` 双推，避免只推一边。
