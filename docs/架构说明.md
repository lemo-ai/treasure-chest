# 架构说明

> 对齐应用 **0.4.0** · 2026-09-18  
> 描述「当前怎么建」，而非早期「打算怎么建」。

---

## 1. 技术栈

| 层 | 选型 |
|----|------|
| 桌面壳 | Electron 43、electron-vite 5、electron-builder |
| 构建 | Vite 7（见 [ADR-001](adr/001-vite7-electron-vite.md)，暂不跟 Vite 8） |
| UI | React 19、TypeScript、Zustand、Motion、react-i18next |
| 本机存储 | better-sqlite3（业务库、知识库、部分缓存） |
| 密钥 | Electron `safeStorage`（及平台能力） |
| 媒体 | ffmpeg-static / ffprobe-static；onnxruntime-web（图片智能处理） |
| 终端 / 编码 | node-pty、xterm（Harness 相关） |

**依赖策略**：优先最新稳定版；与 electron-vite 等工具链冲突时钉主线并记 ADR。

---

## 2. 进程与职责

```
┌─────────────────────────────────────────────┐
│  Main（electron/）                            │
│  窗口 / 托盘 / 开机自启 / 桌面通知             │
│  SQLite · 调度 · LLM 编排 · 知识库 · MCP      │
│  数据源 · 爬虫 · 股票/运势服务 · Harness      │
└─────────────────────┬───────────────────────┘
                      │ IPC（packages/shared）
┌─────────────────────▼───────────────────────┐
│  Renderer（src/）                             │
│  Hash Router · features 页面 · 设置 UI        │
│  只通过 IPC 访问本机能力，不直连 Node 业务库   │
└─────────────────────────────────────────────┘
```

- **主进程**：所有需 Node / 文件系统 / 长驻定时 / 原生能力的逻辑  
- **渲染进程**：按功能分 feature；状态以 Zustand 等本地 store 为主  
- **预加载**：暴露受控 API，避免渲染进程随意 `require`

## 3. 目录约定

```
treasure-chest/
├── electron/                 # 主进程入口与 modules
│   └── modules/              # 按领域拆分（llm、knowledge、schedules…）
├── src/
│   ├── app/                  # 壳、router、布局
│   ├── features/             # 一功能一目录（禁止堆杂目录）
│   ├── locales/              # zh-CN / en-US
│   └── shared/               # 渲染侧共享样式、组件、工具
├── packages/shared/          # 主/渲染共用类型与 IPC channel 常量
├── config/                   # 运行时配置（changelog.json 等）
├── resources/                # 图标、打包资源、预置数据
├── scripts/                  # dev.sh、wasm 同步、图标修补等
├── docs/                     # 本目录
├── electron-builder.yml
└── package.json
```

**新功能**：优先 `src/features/<name>` + 必要时 `electron/modules/<name>` + `packages/shared` 类型；不要把业务堆进 `_template` 或全局杂项。

**主题**：色值与设计 token **只**写在 `src/shared/styles/tokens.css`，页面使用 CSS 变量。

## 4. 主进程模块一览（`electron/modules`）

| 模块 | 职责（摘要） |
|------|----------------|
| `llm` | 对话编排、工具注册、流式输出、内置 tools |
| `localLlm` | Ollama 等本机模型检测与同步 |
| `knowledge` | 入库、切分、FTS/向量检索 |
| `mcp` | MCP stdio/SSE 客户端与工具挂载 |
| `skills` | Skill 安装、内置 Skill、目录源 |
| `dataSources` | 多后端数据源驱动与查询工具 |
| `schedules` | 定时任务调度与执行 |
| `notifications` | 收件箱与通道投递 |
| `fortune` / `stocks` | 运势与荐股领域服务 |
| `crawl` | 网页抓取 |
| `harness` | 编码沙箱（读写文件、shell、git、子 Agent） |
| `calendar` / `tray` / `system` / `settings` | 日历窗、托盘、系统能力、设置持久化 |
| `imageTools` / `tools` | 图片 ONNX 与工具箱相关本机能力 |
| `backup` / `debug` | 备份导出、调试 |

## 5. IPC 与共享包

- Channel 名与 DTO 定义在 `packages/shared`，主/渲染双端引用同一类型  
- 变更协议时**直接改干净**（开发阶段不做旧字段双读双写兼容）  
- 枚举优先使用明确枚举名或数字，避免解析不稳定短名字符串

## 6. 开发与构建

| 命令 | 说明 |
|------|------|
| `npm run dev` | `scripts/dev.sh`：清除 `ELECTRON_RUN_AS_NODE`、同步 wasm、再启动 |
| `npm run typecheck` | node / web / shared 三份 tsconfig |
| `npm run test` | Vitest |
| `npm run build` | typecheck + electron-vite build |
| `npm run dist` | 打安装包到 `release/` |
| `npm run harness` | 无头 Harness |

注意：在 Cursor 等环境若未 unset `ELECTRON_RUN_AS_NODE`，会出现 `electron.app === undefined`。

国内可保留根目录 `.npmrc` 的 Electron 镜像。

---

## 7. 打包要点（`electron-builder.yml`）

- `productName`：袖里乾坤  
- `asar: true`；`ffmpeg-static` / `ffprobe-static` 需 `asarUnpack`  
- macOS DMG 双架构；Windows NSIS 可选目录；Linux AppImage + deb  

---

## 8. i18n

- 文案：`src/locales/zh-CN`、`src/locales/en-US`  
- **禁止**在 UI / toast / 校验里写死单一语言用户文案  
- 发版说明双语维护在 `config/changelog.json`  

---

## 9. 安全与数据边界

- 渲染进程不持有明文长期 API Key  
- 文件系统访问优先经主进程受控 API / Harness 工作区策略  
- MCP Filesystem 等预置服务限制在约定工作区（如 `userData/mcp-workspace`）  
- 爬虫与外网工具需用户显式启用相关能力，并遵守站点协议  

---

## 11. 发版（GitHub Actions）

推送标签 `vX.Y.Z`（或在 Actions 中手动运行 **Release**）会：

1. 用 `config/changelog.json` 生成 Release 说明  
2. 在 macOS / Windows / Linux runner 上执行 `electron-vite build` + `electron-builder`  
3. 将 DMG / NSIS / AppImage / deb 等上传到同一 GitHub Release  

工作流：`.github/workflows/release.yml`。无私有 Apple 证书时跳过公证（`CSC_IDENTITY_AUTO_DISCOVERY=false`）。

历史选型争论见 [`archive/`](archive/README.md)。
