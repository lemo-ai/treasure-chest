# 知识库

> 对齐 **0.4.0** · 2026-09-18  
> 本文描述**已落地行为**。

---

## 1. 目标

本机、无账号的个人知识库：上传与管理文档 → 切分入库 → 关键词 / 向量 / 混合检索 → 工作台对话引用增强。

不做：云同步账号、多租户服务端集群。

---

## 2. 架构（现行）

```
UI（KnowledgePage / 工作台 @知识库）
        │ IPC
        ▼
Knowledge Runtime（electron/modules/knowledge）
  入库 → 解析 → 切分 →（可选）Embedding → FTS / 向量索引
  检索 → 组装上下文 → 引用信息
        │
        ├─ SQLite：文档元数据、切片正文、FTS
        ├─ 向量：默认本机存储；可配置外部向量后端
        └─ 原文件：本地 blobs / 用户选择路径策略
```

权威文本与过滤仍以 SQLite 侧记录为准；向量后端可替换，正文不「只活在向量库」。

---

## 3. 分区（Collection）

- **树形分区**：父子层级（实现上限约 5 层）  
- 操作：新建、重命名、删除  
- 删除策略：可级联清理文档，或移到默认分区  
- 父分区文档数统计包含子分区  
- 分区可与 Agent 绑定，限制检索范围  

页面常见 Tab：文档列表、试检索、向量 / Embedding 设置。

---

## 4. 入库

| 项 | 说明 |
|----|------|
| 格式 | 文本 / Markdown / CSV / JSON / HTML / PDF / Word / PPT / Excel、常见图片等（以解析器支持为准） |
| 去重 / 增量 | `content_hash`；未变更可跳过；变更则替换旧切片 |
| 切分 | 默认 chunk 与 overlap 可配置（常见默认约 700 / 80，以设置为准） |
| 进度 | 入库进度与失败可在 UI 侧感知（具体文案走 i18n） |

系统侧也可将报告、快照等写入知识库（视产品开关与调用方而定）。

---

## 5. Embedding 与向量

| Embedding 模式 | 用途 |
|----------------|------|
| `none` | 仅 FTS 等非向量路径 |
| `local_hash` | 轻量本地方案（无外呼） |
| `openai` / `openai_compatible` / `ollama` | 调用用户配置的接口 |

向量存储：默认偏本机（如 sqlite_json 一类实现）；设置中可对接 Qdrant、Chroma、Pinecone、Weaviate 等（以当前设置枚举为准）。

---

## 6. 检索

- 模式：FTS、向量、**hybrid**（可开关）  
- 工作台：`@知识库` 选区；Agent 工具 `search_knowledge`  
- 回答侧展示引用来源（document / chunk），便于核对  

试检索 Tab 用于调参与验收，不经过完整对话编排。

---

## 7. 与 Agent / 调度的关系

- 自定义 Agent、定时「智能体回合」均可绑定知识库分区  
- 检索结果进入模型上下文；注意 Token 预算与分区范围，避免整库无差别灌入  

---

## 8. 备份

知识库元数据与 embedding 相关配置应纳入设置中的导出 / 备份范围（与会话、设置一并，以备份模块实现为准）。换机需同时考虑原文件 blobs 是否随包导出。
